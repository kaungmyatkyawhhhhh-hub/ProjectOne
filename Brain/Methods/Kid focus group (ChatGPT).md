# Kid focus group (ChatGPT)

**Owner's words:** "u guys are multiple group of kids arguing over which roblox game to play. find the objections they have to yours and improve the game until everyone agrees to play ur game" (9 Nov)
**Use when:** deciding what goes into an update or a new game; "would kids pick our game over X?"; before ads or a big pitch.

## Steps
1. Read the LIVE game in Studio first (what's actually built), not the plan.
2. New ChatGPT chat (Claude drives Chrome). Set up 3 kid groups with names, ages and the real games they play (a grinder group, a chaos / friends group, a cheap-phone group). Rules: stay in character, short and brutally honest, hard to convince, one vote each, a scoreboard every reply (vote + #1 blocker per kid).
3. Pitch the game exactly as it is live. Write down every objection.
4. Each round, answer the top blocker of each kid with ONE concrete change (numbers, odds, timings, how it plays on a phone). No vague promises.
5. Be honest about what's live vs planned. If votes drop, that's the real result: re-frame as "the next update can only hold N features" and let the kids pick.
6. Stop at all-yes (with each kid's condition written down) or when it stalls; the conditions are the acceptance tests.
7. Save: the rounds table, the conditions, the lessons, an audit of live vs missing, and a Claude Code prompt with every change as config values. Don't publish.

## Tools
- Claude in Chrome (one message per round; Enter sends, so use Shift+Enter or one paragraph)
- Roblox Studio MCP for the live audit

## Used on
- 2026-11-09 Galaxy: 0/7 → 1 → 5 → 0 (honesty) → 6 → 7/7 in 6 rounds → [[Celestial Incremental/2026-11-09 Galaxy Incremental - Kid focus group + Prompt - next update (creatures, crew heists, jetpack, phone)]]

## Learned
- Kids judge what they can play TONIGHT: when they learned the features weren't live, votes went 5 → 0. Never advertise unbuilt features.
- Fusing features (stealing + crews + a multiplier) wins more kid types per build than adding features.
- The cheap-phone kid vetoes everything; performance is a feature.
- It's role-play: use it to find objections, confirm with real data (funnel, playtime) after the update.
